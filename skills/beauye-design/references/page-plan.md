# 页面方案

方案是页面中各项决定的共同依据。内容与操作各有明确含义，区域引用这些对象；视觉与行为表达同一优先级，情境变体只记录必要变化。

## 必须回答的问题

- 用户对什么对象完成什么任务？哪些信息用于查看、比较或判断？
- 哪些内容必须可见、必须同时可见，哪些可按需展开？
- 区域如何分配面积、邻近关系与阅读顺序？主要操作作用于页面、区块还是对象？
- 如何用字号、字重、对比、面积、留白表达主次，并保持扫描和可读性？
- 组件如何触发操作、转换状态、反馈结果并支持键盘与触屏？
- 窄屏、长文本、加载、空数据、失败、权限变化与减动时，表达如何变化而能力仍保留？

这些是同一方案中的设计决定，不是五个服务或必须依次调用的阶段。

## 关系约束表达

同时比较的信息保持同一视野和一致格式。表格适合跨对象的多字段比较，数字格式与列对齐支持扫描；窄屏容不下时重排或在表格容器内滚动，不能静默删去关键字段。

共同支持一个判断的依据应邻近或并排。Tab 适合相互独立的内容；判断时必须同时查看的资料不宜被切到不同 Tab。

操作位置跟随作用对象。页面操作靠近页头或工具栏，区块操作靠近所属区块，行操作靠近对应行；批量操作清楚表达所选对象。

阅读顺序表达理解依赖，视觉、DOM 和焦点顺序一致。关键标签与实际错误就近可见，补充解释按需呈现，危险后果在确认时说明；具体判断见[密度规则](density.md)。

## 让选择有任务依据

存在多种可行构图时，比较它们对信息关系和操作的影响。需要多字段批量比较的订单页，表格通常优先；逐单深入处理时，列表与常驻详情可能更合适；图片识别是主任务时，再考虑卡片或画廊。无需为所有任务列举固定数量的候选。

图表和统计卡需要实际分析用途。无依据的概况区可能挤走首屏主要内容；不能因为组件精致就让它取得更高权重。

## 维护整体关系

把字段移入详情、将行操作移到全局工具栏、增加统计区或改变列宽，都可能影响整页关系。检查受影响的比较能力、操作归属、注意力和适配，再修订相关部分。

产品目的、页面设计、架构与实现保持配合。UX 关注理解和操作；DX 与 AX 关注结构清楚、便于维护和继续修改。简单操作不应因设计或实现增加额外理解成本。

用[示例](examples.md)校准方案表达，用[模板](../assets/page-plan.md)承载必要信息。方案记录设计意图，检查事实由执行阶段记录。

方案正文展示整体关系与关键取舍。精确尺寸、状态和执行条件可以放进可展开细则；缺少依据的业务规则、权限、数据格式和操作范围应标为假设或待核对，避免把布局建议当成既定业务事实。
