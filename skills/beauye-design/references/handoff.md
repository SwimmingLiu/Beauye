# 与执行架构交接

页面方案保存设计意图，执行记录保存真实观察。两部分可独立使用，通过同一任务资料衔接，不要求调用者安装另一个 Skill。

## 交接信息

- 用户任务、对象、必须保留与同时可见的信息。
- 修改范围、检查范围及各自来源；项目组件、变量、技术、权限、视口和数据约束。
- 区域与阅读顺序、操作归属、视觉层级、密度、文案及素材选择。
- 组件行为、适用状态、窄屏、长文本、减动和渲染降级的决定。
- 参考来源、具体借鉴关系、关键取舍、假设与待验证项。

已有任务记录能表达时直接复用。[页面方案模板](../assets/page-plan.md)可作为 plan.md。执行端若使用 `.beauye/tasks/<task-id>/task.json`，范围、来源、页面清单、条件和规则版本由该记录统一维护；方案引用记录，不再复制一份手工完成清单。

## 设计、实现与评审

仅设计交付方案，不能附加实现或声称测试通过。仅评审交付具体问题、影响与建议，修改遵循用户授权。已授权实现时携带方案继续完成代码与检查。

可用时使用 `$beauye-execution` 处理执行和校验，也可由 Harness 直接使用项目现有工具。执行 Skill 的安装与 Hook 能力不是形成设计方案的前置条件。

由执行阶段请求补充方案时，只返回或更新方案，由原调用方继续执行。已有任务正在执行时复用其记录与任务标识，避免两个 Skill 相互重复启动任务。

可用 `$beauye-review` 对方案或当前页面独立提出问题。方案审查只能判断设计决定，运行审查另需当前产物。执行阶段维护发现的处理状态；涉及信息取舍、构图与操作关系的建议回到设计，本包不自行维护第二份执行清单。

## 验收基线

从路由、导航、权限整理完整页面清单，真实浏览器逐页检查，包括详情、编辑和菜单外页面。全部页面检查主要桌面视口；修改与受影响页面补查 1440×900、1280×800，支持移动端时补查约 390px。用户明确缩小检查范围时记录其来源。

使用代表性数据观察布局、层级、分组、文字、图标、对齐、间距与溢出。检查关键操作、表单校验、弹层、键盘及适用的加载、空数据、失败、成功、禁用、无权限、长文本、减动和降级状态，查看控制台。新增或明显改版保留截图并对照参考。

修复本次引入的问题，复查受影响页面，运行项目已有 lint、类型检查、构建和相关测试，保留实际结果与证据。

记录标明页面/路由、角色、视口、状态、数据、对应实现与运行条件、实际操作或观察、结果和产物位置。实现或条件变化后重新检查受影响结论。截图不自动证明交互，命令成功不自动证明视觉。

交付列明已查页面、修复内容、验证方式与结果、未验证项及原因。只有实际完成全部页面检查，才报告全系统 UI 已检查。缺工具、权限或数据时说明缺口，不伪造观察或无限重试。

## 回到设计决定

执行发现问题时，定位相应关系：比较困难回到字段、列宽与对齐；主操作难找回到归属与权重；窄屏丢失信息回到重排和容器；整页分散回到主辅区域、边界与间距。必要时修订方案，再复查受影响结果。
