# 审查报告约定

报告先给已确认且影响任务的问题，再列待验证项与可选建议。无问题时写明实际检查范围。报告与其引用的运行证据分开保存。

## 固定本次对象

记录任务与要求来源、检查范围及来源、页面与角色清单、实现指纹或版本、方案与检查约定版本、运行和数据条件。无法确定的值保留未知。截图审查注明文件及所见状态，不声称检查了截图外的页面或交互。

已有执行任务时引用其当前资料与指纹，不维护另一份完成清单。独立审查只维护本报告的覆盖记录。报告来源始终如实标为代理或人工；引用工具产物不改变报告作者身份。

## 每个问题保留可复验信息

| 字段 | 内容 |
| --- | --- |
| 标识与分类 | 稳定问题 ID，已观察缺陷或明确范围内的偏好不符。 |
| 优先级 | P1 表示主要任务受阻或存在错误副作用；P2 表示明确要求不符或影响可用性；P3 表示不阻塞任务的细节。 |
| 要求来源 | 当前用户要求、项目约束或适用设计规则的实际位置与含义。 |
| 位置与条件 | 页面、角色、视口、状态、数据条件和具体区域或控件。 |
| 证据 | 实际截图、动作记录或源码位置。写明所见事实，推断原因另标。 |
| 影响与建议 | 用户会遇到什么问题，建议改变哪项内容、关系或行为。 |
| 复验 | 实际动作、数据条件及可观察的预期结果。 |

明确偏好不符也可以影响验收，其优先级由当前要求和影响决定。不要把它伪装成普遍设计定律。未经要求的另一种风格放在可选建议，不据此阻断交付。

缺少运行证据的推测放入待验证项。写明需要哪项动作才能确认或排除，不列作已确认缺陷。不能从组件名称、源码意图、截图文件存在或构建成功推断交互已通过。

## 表达覆盖与结论

- `needs_work` 表示已有确认问题。报告保留已检查部分与其余未验证项。
- `no_findings_in_reviewed_scope` 表示实际检查范围内未发现问题。它不证明未检查范围，也不表示人工审美偏好。
- `unverified` 表示关键范围缺少证据，暂不能判断。列出缺口与下一项观察。

机器数据可使用 [报告结构示例](../assets/review.example.json)。其中 `example_only` 为 true，不能作为实际审查结果导入。真实报告填写实际对象与证据，不复制示例路径或结论。

执行方按自身观察契约另行保存真实浏览器动作。代理综合判断不能被改写成已执行的工具观察，也不能直接转换成执行检查器的覆盖通过。报告变更、应用指纹和运行条件需一起核对；任一相关条件改变后复查受影响结论，保留旧报告。
