# Beauye 执行与验收

接收用户任务或页面方案，使用当前 Harness 的编辑、命令和浏览器工具完成已获授权的工作。检查器验证记录的一致性、覆盖和新鲜度，不能独立认证浏览器操作或审美质量。

## 先确定范围

读取[交接与任务边界](references/handoff.md)。仅设计交付方案，仅评审交付问题与建议；要求实现时完成实现和检查。修改范围与检查范围分别记录，不能因为只改一页就自动缩小验收。

按需读取[页面检查要求](references/checking.md)。默认从路由、导航、权限整理完整页面清单，包含详情、编辑和菜单外页面；全部页面检查主要桌面视口，修改和受影响页面补充指定视口。用户明确缩小范围时记录来源。

已有方案直接接收，不要求另一个 Skill 已安装。缺少方案时，根据用户任务和已确认的同类页面补足必要设计决定。沿用兼容的已有业务组件；新项目默认 Vite、React、TypeScript、Base UI、Tailwind 和 shadcn/ui 的 Base UI 版本。选型更新不自动授权存量迁移。

## 建立本次任务资料

运行随包脚本，使用实际的 Skill 路径和项目路径：

```bash
python3 <skill-dir>/scripts/beauye.py init --project <project-root> --task <task-id> --mode implement --plan <existing-plan>
```

`mode` 可为 `implement`、`review`、`design`。没有现成方案时省略 `--plan`。默认目录是项目中的 `.beauye/tasks/<task-id>/`；同名任务不会被覆盖。填写任务、修改范围与来源、检查范围与来源、页面清单和实际运行条件。已有任务资料可由 `plan_path` 引用，范围和清单由任务记录统一维护。

首次记录时读取[记录契约](references/records.md)。[页面方案模板](assets/page-plan.md)、[任务示例](assets/task.example.json)和[观察示例](assets/observation.example.json)用于填写结构，示例不代表已检查。

## 编写前后使用同一检查器

```bash
python3 <skill-dir>/scripts/beauye.py check --task-dir <task-dir> --phase before-write
python3 <skill-dir>/scripts/beauye.py check --task-dir <task-dir> --phase after-edit
python3 <skill-dir>/scripts/beauye.py check --task-dir <task-dir> --phase delivery
```

编写前确认适用方案与范围；修改后取得当前输入指纹、识别旧证据；交付前对照清单汇总缺口。脚本只检查记录和文件，不执行任务中填写的项目命令。完整工程和浏览器检查按合理批次运行。

使用项目已有 lint、类型检查、构建和相关测试。通过 Harness 的真实浏览器能力检查页面、操作、状态、键盘与适配，记录实际观察、结果和产物。修复本次引入的问题并复查；其他问题记录位置，代码修改保持在授权范围。

<!-- 自动专项曾被误用为整页认可；独立审查与修复循环由同一执行任务组织。 -->
取得当前可运行页面后，可用 `$beauye-review` 独立审查整页和适用状态。提供用户要求、方案、页面清单、实现指纹与真实浏览器产物，接收具体问题和建议。审查默认只读，不另建执行任务。将每项发现记录为采纳、已有依据不采纳或仍待验证；采纳后修改并复查。改变区域、信息或操作关系时，先更新设计方案再继续实现。

按用户能够完成的完整任务片段实现。页面结构、样式、入口脚本和实际操作在同一片段内交付，再完善视觉与适配；避免先堆叠全部静态区域，留下缺失的业务脚本。外部验证与生成明确分开时，生成阶段完成可运行文件，真实检查由指定验证阶段执行。

每份观察明确页面、角色、视口、状态、数据条件、实现指纹、实际动作、预期与结果、证据来源和产物位置。工具执行、人工观察与代理陈述分别记录；仅有代理陈述不能计作真实操作通过。不要创建模拟截图或捏造工具调用标识来补齐验收。

应用源码、配置、依赖、素材或任务检查约定变化后，第一版保守地要求旧观察复查。清单中的路由、角色、视口和要求同样参与证据关联。外部数据、运行版本和角色条件另行确认；源文件未变不能证明运行画面未变。缺工具、权限或数据时保留未验证及原因。

Review 的代理判断单独保存并标明依据，不能改写成工具执行或人工审美偏好。没有 Review 包时，当前执行者按同样维度完成审查，明确独立性限制；本 Skill 仍可独立使用。记录检查器报告覆盖完整，不等于页面已通过审美评判。

## 交付与可选 Hook

交付列明已检查范围、修复内容、实际结果与未验证项。覆盖结论来自当前检查记录；只有完整清单及其必检项实际完成，才能报告全系统 UI 已检查。纯设计交接不产生运行通过声明。

需要宿主事件接入时再读取[可选 Codex Hook](references/hooks.md)。适配器复用同一检查器，不启用全局配置，不接管浏览器或图片供应商。没有 Hook 仍可主动调用；结束事件最多自动请求一次补查，不能因条件缺失而持续续跑。
